# 3x-ui 2.9.4+21 — подробное описание изменений

Текущая версия панели в этой ветке: **`2.9.4+21`**.

- `2.9.4` — базовый релиз 3x-ui.
- `+21` — идентификатор набора дополнительных патчей совместимости. Это не
  отдельный Xray-релиз и не переход на 3x-ui 2.9.5.
- Целевая версия Xray-core: **v26.9.30**, commit `b26a91d`.
- Сборка панели переведена на Go 1.27, необходимый текущему Xray-core.

## Кратко

В 2.9.4 добавлены обновление панели из веб-интерфейса, более быстрые таблицы и
WebSocket-обновления для больших баз клиентов, VLESS reverse, новые фильтры и
несколько исправлений безопасности. В варианте `2.9.4+21` дополнительно
реализован слой совместимости с изменениями Xray v26.4.25–v26.9.30: XHTTP,
FinalMask, REALITY ML-KEM, TUN, Hysteria, TLS pinning, новые подписки,
миграции конфигурации и безопасное обновление ядра.

## Изменения базового 3x-ui 2.9.4

### Панель и обновление

- Добавлено обновление панели из веб-интерфейса.
- Улучшена проверка версий панели: корректно сравниваются версии с префиксом
  `v`, минорные и мажорные обновления.
- Добавлена настройка автоматического перезапуска Xray после автоматического
  отключения клиента.
- На странице подписки отображается состояние `enabled`.
- Добавлен фильтр активных inbound-подключений.

### Производительность интерфейса

- Переработаны WebSocket-обновления inbound-таблиц.
- Уменьшено количество полных перерисовок и лишних уведомлений.
- Улучшена работа с inbound, содержащими тысячи клиентов; целевой сценарий —
  базы порядка 10 000 и более клиентов.
- Исправлена синхронизация статистики, состояния клиентов и модальных окон.

### Xray и маршрутизация

- Правило маршрутизации API при сохранении закрепляется первым, чтобы более
  общие правила не перехватывали API-трафик.
- В Freedom outbound добавлено поле `finalRules`.
- Добавлен простой VLESS reverse proxy.
- Обновлены значения по умолчанию и валидация QUIC.
- Удалён устаревший переключатель принудительного ECH-запроса.
- Из списка REALITY target удалены неподходящие варианты Apple/iCloud.
- Исправлен подсчёт клиентов Hysteria.

### Безопасность и надёжность

- Входящие заголовки с удалённым IP очищаются перед использованием.
- Вывод просмотрщика логов экранируется, чтобы содержимое лога не исполнялось
  как HTML/JavaScript.
- API проверяет существование клиента перед операциями с ним.
- Обрабатываются ошибки сканера при чтении логов Xray.
- Обновлены зависимости Go.

## Совместимость Xray v26.4.25–v26.9.30

### 1. XHTTP session ID

- `sessionPlacement` автоматически мигрирует в `sessionIDPlacement`.
- `sessionKey` автоматически мигрирует в `sessionIDKey`.
- Добавлены `sessionIDTable` и `sessionIDLength`.
- Новые поля доступны для inbound и outbound.
- Импорт старых ссылок остаётся совместимым.
- Новые значения попадают в share links, `extra=` и Mihomo YAML.

### 2. XHTTP/3, padding и XMUX

- Добавлены настройки и подсказки XHTTP/3 и `udpHop`.
- UI предупреждает о необходимости согласовать `udpHop` и `dialerProxy`.
- Поддерживаются `xPaddingBytes`, `xPaddingObfsMode`, ключ и заголовок obfs.
- Добавлены актуальные XHTTP-поля `scMinPostsIntervalMs`, `noGRPCHeader` и
  `serverMaxHeaderBytes`.
- Настройки XMUX/concurrency доступны в UI.
- Старые сохранённые значения, повторявшие прежние defaults ядра, удаляются
  миграцией. Пользовательские значения сохраняются.

### 3. gRPC и реальный IP клиента

- Для gRPC inbound доступен `sockopt.trustedXForwardedFor`.
- Добавлены подсказки для reverse proxy/CDN.
- При выборе Xray v26.9.30 панель предупреждает о deprecation gRPC и известном
  риске восстановления outbound после разрыва соединения.

### 4. WireGuard

- Удалены больше не поддерживаемые `workers` и `num_workers`.
- Старые значения тихо удаляются при чтении конфигурации.
- Для схемы v26.9.30 удаляются устаревший `domainStrategy` и некорректный
  локальный режим `remoteDNS`.
- `remoteDNS`, сохранённый строкой, нормализуется в массив.

### 5. TUN

- Добавлены `autoSystemRoutingTable` и `autoOutboundsInterface`.
- Учтены поля v26.9.30 `autoSystemDnsToGateway` и
  `autoSystemWfpBlockLeak`.
- MTU приведён к текущей схеме Xray: одно число вместо старого массива.
- Старый массив MTU мигрирует с сохранением первого значения.
- Linux-панель проверяет `/dev/net/tun`, root, `CAP_NET_ADMIN` и
  `CAP_NET_RAW`.
- На Windows проверяется запуск с повышенными правами.
- Вложенные имена TUN-счётчиков Xray распознаются статистикой панели; работают
  обычные графики и сброс трафика inbound.

Для контейнера на Ubuntu обычно требуются устройство `/dev/net/tun` и
capabilities `NET_ADMIN`/`NET_RAW`. Панель показывает фактическую готовность,
а не только наличие настроек в JSON.

### 6. Hysteria и Hysteria2

- Добавлен `vlessRoute` в правила маршрутизации.
- Значение экспортируется в Hysteria2 share link и Mihomo `vless-route`.
- Старые формы `hysteria2`/`hy2Settings` нормализуются в текущую модель Xray.
- FinalMask и Salamander obfs экспортируются без потери параметров.

### 7. FinalMask

- В UI разделены TCP- и UDP-маски.
- Добавлен XMC с проверкой имени профиля, UUID, секрета, texture value и
  signature.
- Неполный или повреждённый XMC не сохраняется и удаляется миграцией с
  предупреждением.
- Поддерживаются XICMP, актуальная объектная схема XDNS, `header-*`, `mkcp-*`,
  Salamander и QUIC/UDP hop.
- Для XDNS доступны домены с лимитами, типами запросов и EDNS0, TCP/UDP
  resolvers и `extraPoll`.
- Старые строковые записи XDNS мигрируют в объектную форму.
- Параметры переносятся через компактные поля `fm`, `pcs`, `vcn` или через
  `extra=` при отсутствии стандартного параметра ссылки.

### 8. REALITY, ML-KEM и fingerprint

- Добавлен режим совместимости `X25519MLKEM768`.
- Реализованы генерация и проверка `mlkem768` seed/client key.
- Для Mihomo при включённом режиме выводится:

  ```yaml
  reality-opts:
    support-x25519mlkem768: true
  ```

- Если fingerprint не задан, Mihomo получает безопасный default `chrome`.
- UI предупреждает о старых fingerprint/uTLS и клиентах Shadowrocket.
- Отдельно показано, что обычная ссылка `vless://` не переносит флаг
  `support-x25519mlkem768`.
- Пустой `minClientVer` означает отсутствие минимальной версии.
- Старое встроенное значение `26.3.27` очищается при миграции.
- Явно заданный минимум сохраняется.
- Добавлены пресеты строгих современных клиентов и максимальной
  совместимости.

### 9. TLS verification и pinning

- Добавлены `pinnedPeerCertSha256` и `verifyPeerCertByName`.
- В UI можно получить SHA-256 leaf-сертификата через `xray tls ping`.
- Проверяется формат pin и имени проверки.
- Устаревший `allowInsecure` больше не превращается в
  `skip-cert-verify: true` при экспорте.
- Старые TLS-поля мигрируют в безопасную модель проверки/pinning.

### 10. HTTP headers и User-Agent

- Для outbound XHTTP/HTTP можно задать произвольные HTTP headers.
- Можно явно переопределить `User-Agent`.
- Если override пуст, UA не фиксируется панелью: Xray самостоятельно выбирает
  динамический Chrome User-Agent.
- Headers сохраняются в `extra=` для форматов ссылок без стандартных полей.

### 11. MPH domain matcher и geodata

- Панель отображает автоматический режим MPH и жизненный цикл кэша.
- Показываются HIT/MISS, продолжительность запуска и признак slow start.
- Ошибки загрузки `geosite.dat`/`geoip.dat` видны в диагностике.
- Показываются путь, размер и состояние geodata-файлов.
- Кнопка rebuild очищает process-local cache безопасным перезапуском Xray.

### 12. VLESS reverse

- Добавлен UI для VLESS reverse account и reverse outbound.
- Для диапазона Xray v26.5.x–v26.6.1 показывается предупреждение о известной
  несовместимости.
- Старые top-level bridge/portal можно сопоставить новым VLESS reverse tags.
- Доступна проверка живого туннеля через TCP или HTTP/HTTPS endpoint.
- После смены ядра панель рекомендует повторный tunnel test.

### 13. Предупреждения об устаревших конфигурациях

Панель помечает и умеет фильтровать:

- VMess;
- Trojan без Flow;
- VLESS без Flow;
- legacy Shadowsocks;
- конфигурации с `allowInsecure`;
- gRPC для актуальных версий ядра.

Добавлен мастер преобразования устаревшего inbound в современный VLESS с
REALITY/Vision. Перед преобразованием показываются рекомендуемые изменения.

### 14. Безопасное переключение Xray release

- Матрица учитывает v26.4.25, v26.6.22, v26.6.27, v26.7.28, v26.9.8,
  v26.9.9 и v26.9.30.
- До установки показывается список затронутых inbound.
- Сначала генерируется полный конфиг панели.
- Загруженный candidate core запускается с `run -test` на этом конфиге.
- Только после успешной проверки текущий бинарник заменяется.
- При ошибке запуска предыдущий core автоматически возвращается и
  перезапускается.
- Для REALITY + Shadowrocket выводится отдельное ML-KEM-предупреждение.

### 15. Share links и подписки

- Расширен `vless://` для XHTTP, FinalMask и REALITY-параметров.
- Не стандартизованные поля сохраняются в JSON `extra=`.
- Mihomo YAML получает XHTTP/FinalMask extras, `vless-route`, TLS overrides и
  ML-KEM capability.
- Для официального sing-box генератор выдаёт понятную ошибку на XHTTP или
  FinalMask вместо создания JSON, который клиент всё равно отвергнет.
- Генерация учитывает возможности формата и выбранного клиента; отсутствие
  поддержки не маскируется под успешный экспорт.

## Автоматические миграции

При загрузке и сохранении старой конфигурации нормализуются:

- XHTTP `session*` → `sessionID*`;
- прежние defaults XMUX/concurrency;
- WireGuard `workers`, `num_workers`, `domainStrategy`, `remoteDNS`;
- старый TUN MTU;
- REALITY `minClientVer`;
- неполный FinalMask XMC;
- legacy FinalMask UDP/XDNS;
- TLS `allowInsecure` и pinning-поля;
- старые Hysteria/Hysteria2 settings.

Миграция выполняется идемпотентно: повторная обработка уже актуального JSON не
должна менять пользовательские значения.

## Проверка совместимости

Для релиза добавлены воспроизводимые fixtures:

- `testdata/xray-v26.9.30-compat.json`;
- `testdata/mihomo-v1.19.32-compat.yaml`;
- `testdata/sing-box-v1.14.1-compat.json`.

Они проверены реальными бинарниками Xray v26.9.30, Mihomo v1.19.32 и sing-box
v1.14.1. Дополнительно проходят unit-тесты миграций, ML-KEM, TLS pin parser,
TUN counters, geodata diagnostics и генераторов подписок, `go vet ./...`,
проверка JavaScript-синтаксиса и cross-build `linux/amd64`.

Два старых SQLite integration-теста требуют CGO. На локальном portable Go под
Windows они не запускаются; Docker/Ubuntu builder содержит GCC и собирает
панель с CGO.

## Что проверить после обновления

1. Сделать резервную копию базы панели и текущего Xray binary.
2. Открыть план обновления Xray и проверить список affected inbounds.
3. Для REALITY убедиться, что используемые клиенты поддерживают ML-KEM.
4. Для gRPC проверить восстановление соединения после перезапуска peer либо
   перейти на XHTTP stream-up.
5. Для TUN проверить `/dev/net/tun` и capabilities контейнера/процесса.
6. Проверить geosite/geoip diagnostics и длительность старта Xray.
7. Повторно протестировать VLESS reverse tunnel.
8. Перегенерировать Mihomo/sing-box подписки и проверить предупреждения
   конкретного формата.

## Готовый Docker-образ

Multi-arch образ публикуется в GitHub Container Registry:

```text
ghcr.io/lagnuty/3x-ui:2.9.4-21
```

Поддерживаемые платформы: `linux/amd64`, `linux/arm64`, `linux/arm/v7` и
`linux/386`. В образ встроен Xray v26.9.30. На сервере достаточно выполнить
`docker pull`; локальная сборка проекта не требуется. Готовые команды запуска
приведены в `README.ru_RU.md`.

## Известные ограничения

- Raw `vless://` не передаёт Mihomo-флаг ML-KEM.
- Shadowrocket и старые клиенты могут быть несовместимы с REALITY новых
  версий Xray.
- Официальный sing-box v1.14.1 не поддерживает XHTTP и FinalMask как Xray.
- В Xray v26.9.30 отмечен риск gRPC reconnect после потери соединения.
- XDRIVE и MASQUE появились в новой ветке Xray, но не входят в реализованный
  набор 1–22: отдельных редакторов и форматов подписок для них пока нет.

Подробная техническая матрица находится в
[`XRAY_V26_COMPATIBILITY_AUDIT.md`](XRAY_V26_COMPATIBILITY_AUDIT.md).

Полный каталог новых элементов интерфейса, JSON-путей, типов, defaults,
валидации и экспорта находится в
[`XRAY_26_UI_FIELDS_RU.md`](XRAY_26_UI_FIELDS_RU.md).
